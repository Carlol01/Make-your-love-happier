CSV / JSON generico stabile

Il formato più semplice: funziona con qualunque app, o a mano.

Che cosa serve: Un CSV o JSON con inizio e fine dei periodi.
Dove va: nel secret del repository o in data/imports/ / sync --file, come indicato sotto.

Procedura

CSV:

start_date,end_date,note
2026-10-24,2026-10-28,
24/10/2026,28/10/2026,anche dd/mm/aaaa

JSON (end può essere null se il periodo è in corso):

{"periods":[{"start":"2026-09-26","end":"2026-09-30"},{"start":"2026-10-24","end":null}]}
  1. Salva il file in data/imports/ (verrà letto una sola volta) oppure usa python -m cycle_notifier sync --file periodi.csv.
  2. Per aggiungere un singolo periodo: python -m cycle_notifier add-period 2026-10-24 2026-10-28.

Limiti da conoscere

  • Le date ambigue (03/04/2026) seguono date_order in config/config.toml; le date ISO (AAAA-MM-GG) non sono mai ambigue.
  • Date nel futuro o precedenti al 2000 vengono scartate con un avviso.

Affidabilità della fonte: stabile = formato documentato; best-effort = formato non documentato, letto in modo tollerante; non ufficiale = accesso senza API pubblica, può smettere di funzionare.

Sito statico e pubblico: non contiene dati personali. Le previsioni sono stime automatiche, non consigli medici.
